# 交付方式

## 先给理论结果

默认先给最终命题和结论状态，再给必要假设、推导与含义。用户要求初稿或润色时，优先交付实际段落；用户要求形式化时，同时交付真实 Lean 文件和检查记录。不要只返回“应该证明什么”的建议清单。

状态绑定具体命题与产物。原命题被反例否定、修订命题已证明、辅助 Lean 片段未运行，可以同时成立；分别记录，不将三者压成一个“理论已通过”。实际格式见 [返回协议](../../interfaces/methods.md)。

小任务可以在一次回复中完成；复杂任务按下列产物组织，不强制每次创建全部文件：

| 产物 | 内容 |
| --- | --- |
| 理论说明 | 假设、定义、量词、命题、引理、证明或反例 |
| 覆盖说明 | 支持的主张、实际算法差异、未完成应用条件 |
| Lean 工程 | 固定版本、完整源码、入口定理、依赖锁定 |
| 运行记录 | 构建与审查命令、退出状态、日志、源码散列 |
| 正文文字 | 成立条件、准确结论、证明思路、方法意义 |

## 不能完成时仍交付可用部分

缺失定义时指出缺什么；命题为假时给出反例；证明卡住时定位具体引理。未运行源码与检查失败分别记录，不能写成验证通过。仅有模板引理通过而应用条件尚未证明时，报告“通用引理已检查，当前方法未完成实例化”。

所有 `[待补：…]` 指向具体材料或推导。代码工程中的已声明定理不使用占位证明交付为完成产物；未解决的命题保存在义务清单中，源码若保留实验性占位必须单独隔离并标为未完成。

## 可复用的状态摘要

> 在 {{ASSUMPTIONS}} 下，已建立 {{EXACT_STATEMENT}}。证明覆盖 {{FORMAL_OBJECT}}；实际方法中的 {{IMPLEMENTATION_GAP}} 仍需要 {{MISSING_OBLIGATION}}。Lean 状态为 {{OBSERVED_STATUS}}，检查记录位于 {{REAL_LOG_LOCATION}}。

字段按实际结果填写，省略不适用项。没有实现差异时不虚构限制，没有运行时不生成日志路径。
