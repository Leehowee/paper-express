# 审查与前四部分的接口

这是上下文传递协议，不是自动调用服务。审查模块独立可用，不要求用户先运行写作模块。接收已有材料，不重复索要同一信息；审查时回看原稿及实际证据，不能仅根据其他模块的“完成”说明作判断。

## 输入

最小输入为待审材料、版本或可区分的标识，以及审查任务。目标 venue、主张清单、原始结果、证明、图表源码与前次意见按需要提供。完整可复制格式见 [review-request.yaml](../assets/templates/review-request.yaml)。

写作模块传入时附：研究问题、核心主张及位置、正文与附件、目标路线、已核实投稿约束、证据状态和待定事项。摘要或单节任务不能标记为全文审查。

## 返回

返回审查范围、报告、主张状态、问题台账、修改优先级、可选增强和未评估事项。重要问题统一保留 issue_id、claim_id、版本、位置、依据、严重程度、动作和关闭标准。

与其他模块交换状态时按 [共用上下文](../../shared/research-context.md) 对齐，区分数学命题、Lean 工程、图表产物和审稿问题。没有提供该共用文件时，按本接口的具体材料与检查范围完成独立审查即可。

当需要落实修改时，每项形成以下任务：

```yaml
issue_id: null
claim_ids: []
manuscript_version: null
evidence_locations: []
problem: null
requested_action: null
constraints_and_assumptions: []
closure_test: null
affected_sections: []
return_artifacts: []
```

## 路由

| 问题性质 | 对接模块 | 需要返回的实际结果 |
| --- | --- | --- |
| 问题不重要、差异模糊、研究假设不清 | [Idea 与问题审查](../../paper-idea-review/SKILL.md) | 修订问题、近邻差异、检验路线及其证据边界 |
| 已有证据未写清、主张过强、正文附录分工不当 | [论文写作](../../paper-writing/SKILL.md) | 实际修改稿与变更位置；不得以润色掩盖缺失证据 |
| 假设、证明、反例、实现适用性或形式化覆盖 | [数学理论](../../paper-theory/SKILL.md) | 命题、证明或反例，以及真实数学／Lean 状态与应用条件 |
| 图表口径、编码、来源、表注与正文不一致 | [科研图表](../../paper-figures-tables/SKILL.md) | 由已核实数据生成的修订图表、源文件、图注与检查记录 |
| 需要新数据、新实验、训练或外部复现 | 明确的研究执行任务 | 设计、条件、资源与实际结果；不是现有四个模块能凭文字生成的证据 |

问题可涉及多个模块，但先解决其依赖。例如先修正数据汇总，再重画，再改写结论；先确定命题成立范围，再改 Methods、摘要与结论。

模块返回后，审查方按原关闭标准核对新材料。不得因模块被调用就标记问题解决。`resolved_by_narrowing` 必须记录主张变弱了什么；修改后出现的新证据可改变原评价。

仅要求审查时，交付报告与任务单即可；用户要求同时修改时，在已有授权范围内执行可完成的修改并返回复核结果。接口不授权发送邮件、提交期刊评审、上传保密稿件或启动未授权的大型运行。
