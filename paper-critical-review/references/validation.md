## 合成示例的实际复核

读取 `assets/examples/illustrative-results.csv`，用 Python 标准库 `Fraction` 计算三个差值：`4, 2, -2` 个百分点；等权平均为 `4/3`，显示到两位小数为 `1.33`。因此原合成摘要的“均提高”和“平均提高 3 个百分点”均与表格矛盾。

对反例 `f(x)=x², x[t]=1`：平方非负；常数序列满足每一步目标非增；极限点为 1，其目标值 1 大于 x=0 处的目标值 0。数学条件逐项核对，并用本地计算确认示例数值。它否定的是所给一般命题，不能推出未提供完整更新的 RR 算法在所有任务失败。

按 v2 的实际演示改动复核五个问题：I01、I02、I03 为 `resolved_by_narrowing`，I04 仍 `open`，I05 为 `resolved`。没有新增数据、机制证明或 Lean 执行，因此不把关闭问题写成原强主张获证。

## 行为边界自检

以下为编制者对照模板开展的人工情景检查，不是独立代理评测，也不是自动化科学判断测试。

| 输入情景 | 本次采用的处理 |
| --- | --- |
| 只有摘要与表格，要求审查整篇 | 先查可见结论，明确未检查范围；不推定全文没有理论或消融 |
| 只见重叠误差条 | 不由重叠直接判断差异或等效；先识别统计量与比较设计 |
| 表格口径未定义 | 记录 `aggregation_ambiguity`，不直接判定算术错误 |
| 条件引理源码被称为完整 Lean 验证 | 分开记录未运行状态与语义覆盖；不要求普通经验论文必须形式化 |
| 重复数值或相似图像 | 定位异常并请求来源核验，不直接作不端指控 |
| 用户要求 best paper 视角 | 在有效性审查后检查洞见与可迁移价值；可选提升与必修问题分开 |
| 同一上下文给出多个视角 | 标为多视角分析，不声称独立审稿或共识 |
| 作者承诺未来补实验 | 保持未关闭；实际新材料出现后才核验 |
| 新稿撤回不成立的强主张 | 允许按收缩解决，并重新评价剩余贡献，不称原主张获证 |
| 原意见误读已有附录 | 使用 `withdrawn` 撤回误判，不算作者新增修复 |
