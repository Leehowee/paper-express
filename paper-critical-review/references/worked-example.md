# 合成稿件 → 审查 → 修改后核验

本文件全部方法名、数据、稿件及修改均为教学构造，不是任何作者论文的结果。它演示如何使用模板，不是实际投稿评审或独立审稿人实验。结果数据见 [illustrative-results.csv](../assets/examples/illustrative-results.csv)。位置以本文件 S1–S6、V2.1–V2.5 标识，不虚构 PDF 页码。

## A. 提供给审查者的材料：演示稿 v1 摘录

**S1 — 摘要与贡献。** 方法 RR 通过新损失 L1 和更新规则 A1 提高分类效果。在 D1、D2、D3 上准确率均提高，跨数据集等权平均提升 3 个百分点。收益来源于 L1 的噪声抑制机制。算法保证收敛到全局最优，且该结论已由 Lean 验证。

**S2 — 协议。** 基线使用 L0+A0，RR 使用 L1+A1。两者使用相同训练、验证、测试划分、模型骨干、预训练权重、硬件和 100 次更新预算。学习率均为 0.1。Table 1 为单次固定运行的准确率（%），不声称统计显著性。跨数据集平均为三个数据集等权平均。

| Table 1 | D1 | D2 | D3 |
| --- | ---: | ---: | ---: |
| 基线 L0+A0 | 80 | 70 | 60 |
| RR L1+A1 | 84 | 72 | 58 |

**S3 — 命题 1。** 对任意非负实值目标函数 f，若算法产生序列满足所有 t 上 `f(x[t+1]) ≤ f(x[t])`，则该序列必收敛到 f 的全局最小点。原稿证明只写“目标单调且有界，所以结论成立”。

**S4 — 所提供的 Lean 片段。**

```lean

theorem oneStep (f : ℝ → ℝ) (x y : ℝ)
    (h : f y ≤ f x) : f y ≤ f x := h
```

**S5 — 实验讨论。** “由 Table 1 可知，L1 的噪声抑制机制导致性能提升。”所给材料没有 L1+A0 或 L0+A1 的交叉对照，也没有机制干预。配置说明写“步长 λ=0.1”，而算法说明把同一学习率称为 η。

**S6 — 材料边界。** 本次只提供 S1–S5 摘录与 Table 1。未提供相关工作全文、原始运行日志、其他实验或完整算法代码。不能据此断言整篇论文没有这些内容。

## B. 按 TPAMI 视角形成的实际审查报告

### 范围与概括

本次检查演示稿 v1 的 S1–S6 及合成结果表，采用 TPAMI 技术与证据视角。本文同时修改损失和更新规则，并报告三个数据集的单次固定运行结果。结果表支持在 D1、D2 上取得更高的数值准确率，但不足以支持摘要中的全条件收益、提升幅度、机制归因与全局最优保证。最近邻文献、完整算法实现及运行可复现性暂不能判断。

### 有证据的优点

**S01。** S2 明确了共享资源、更新预算和结果汇总方式，使表中描述性比较可解释；Table 1 保留 D3 的不利结果，使适用边界可见。没有误差数据时明确写单次固定运行，也避免了虚构均值或显著性。

### I01：摘要与结果表矛盾 — major，blocking: true，P0

受影响主张 C01 位于 S1；证据为 S2 Table 1。逐数据集差值为 +4、+2、−2 个百分点，等权平均为 4/3，即约 1.33 个百分点；D3 并未提升。S1 的“均提高”和“平均提升 3 个百分点”因此被已给材料直接否定，主张状态为 `refuted`，审计状态为 `confirmed_internal_error`。

这是摘要主结果的范围和数值错误，而非局部措辞偏好。请依据现有表格修正摘要和所有引用：D1、D2 的数值更高，D3 更低，等权平均提高约 1.33 个百分点。关闭条件是新稿所有相关表述与相同表格及汇总口径一致，不需要为了维持“均提高”而删除 D3。

### I02：单调性不能推出全局最优 — major，blocking: true，P0

受影响主张 C02 位于 S1、S3。取 `f(x)=x²`、所有 t 上 `x[t]=1`。目标非负，且每步目标都为 1，满足 S3 的全部单调性前提；序列收敛到 1，但全局最小值在 x=0 处为 0。这是满足前提的反例，因此命题 1 为 `refuted`。

请加入足以推出所需结论的真实条件并重新证明，或撤去全局最优保证。仅由单调且有下界可讨论目标值序列的收敛，不能据此推出迭代点或全局最优性。本反例否定 S3 的一般命题；由于完整 RR 更新未给出，它不证明 RR 在每个实际任务上都会失败。

### I03：形式化材料未覆盖所声称结论 — major，blocking: false，P1

受影响主张 C03 位于 S1，证据为 S4。`oneStep` 的结论就是其前提 h，仅表达一个已假设不等式；它没有编码迭代过程或全局最优性。材料也未提供可核实的构建记录。该片段记录为 `lean_status: source_unrun`；尚无对应编码的算法保证则为 `not_formalized`。不能据此判定构建成功或失败，更不能认定 C02 已得到形式化验证。

这项问题独立影响验证可信度；核心数学结论的阻断理由已由 I02 记录。请完成原命题到编码的语义映射、应用条件和实际验证，或删除完整验证的表述，将该片段明确标为未运行的条件引理示例。关闭条件包括正文验证范围与实际资产一致，不要求为了保留经验结果强制完成 Lean 工程。

### I04：现有比较不能确定损失的机制贡献 — major，blocking: false，P1

受影响主张 C04 位于 S1、S5，证据是 S2 同时改变 L 和 A 的两行结果。该比较只描述整体系统差异，无法区分新损失、新更新及其交互作用；也没有直接测试噪声抑制机制。因此 C04 为 `unsupported`，不等于机制已被反驳。

建议先用可行的 L1+A0 与 L0+A1 控制区分贡献来源；若保留“噪声抑制导致”这一机制结论，还需能区分相应解释的定向分析。也可直接将贡献限定为完整系统在已测条件下的结果，并撤去未经建立的机制归因。原始表中的数值比较不因本意见自动失效。

### I05：学习率符号不一致 — minor，blocking: false，P2

S5 的步长 λ 与算法说明中的 η 对应同一学习率，且 S2 已给出一致数值 0.1。请统一符号，并核对配置和正文。本项在所给材料中不改变数值比较或理论判断。

### 待核实与可选提升

文献创新性、原始运行重现及其他条件下的效果因 S6 的材料边界暂不能评估，不据此推断作者没有开展相关工作。若希望把单次固定运行观察扩展为稳定性能结论，需要相应重复与不确定性分析，不能从当前表格计算显著性。

**O01，可选增强。** 在当前条件结果成立之后，研究什么数据条件使 L1+A1 在 D3 不利，可能形成可迁移的设计认识。若不将该原因写成现有贡献，这项研究不是修正 I01 所必需的工作。

### 修改顺序

先修正 I01 的明确结果矛盾，并决定 I02 的理论保证是修复还是撤回；据此处理 I03 的形式化声明。随后解决 I04 的归因，最后统一 I05 的符号。新实验尚未发生，不补写任何预计成绩。
