# 主张审计

检查项目由论文承诺的结论触发。下表用于发现最关键的断点，不是所有论文必须完成的实验清单。

| 主张类型 | 必须看清的关系 | 能改变判断的证据 |
| --- | --- | --- |
| 问题重要 | 限制是否真实、在哪些条件影响谁 | 现实约束、失败频率、实测动机、可核查的学科后果 |
| 实质创新 | 相对最近邻工作改变了什么 | 同任务、信息、假设、成本下的贡献差异；核实的文献定位 |
| 方法合理 | 设计是否针对明确障碍 | 目标与操作对应、消融或逻辑推导、适用条件 |
| 性能更好 | 提升来自什么、比较是否公平 | 匹配协议与预算、合适基线、差值和不确定性 |
| 机制成立 | 被观察现象是否足以区分解释 | 针对关键变量的干预、控制混杂或更弱且准确的措辞 |
| 理论保证 | 证明的对象是否就是实际声称对象 | 完整条件、量词、推导、实现映射；必要时形式化日志 |
| 泛化或稳健 | 证据覆盖了哪些变化 | 与主张对应的域、噪声、模型、预算和失败条件 |
| 资源更省 | 节约的资源与性能代价是什么 | 同硬件协议、端到端成本、训练与推理边界 |
| 资源或数据贡献 | 资源是否可用、覆盖与质量是否支撑用途 | 来源、质量控制、划分、覆盖分析、使用约束 |
| 可解释或可视化 | 图中结构是否对应原变量和任务 | 编码定义、量化支撑、案例选择、替代解释 |

## 贡献类型校准

问题驱动论文检查终点与约束；理论驱动论文检查新命题、假设强度与证明；机制论文检查竞争解释；方法论文检查增益来源与代价；资源论文检查新增能力、质量和可复用性；负面结果检查被否定命题的边界和评估强度。新知识不只等于新增模块或榜单第一。

## 创新性审查的写法

先确认“最近邻”的证据，而非凭题目或技术名相同下结论。至少比较研究目标、可用信息、核心操作、成立条件与可达到结论；仅选择与所质疑主张有关的维度。

检索未完成时写“尚未建立与已核实工作 X 在条件 Y 下的区别”，不要写“没有创新”。要求增加引文应说明它怎样改变定位或解释；不要求无关引用，不将新近出现且超出历史截止时点的论文当作当时遗漏。

## 贡献与呈现的区别

已有关键结果但论证隐藏，可通过重组恢复；没有相应证据，不能只把措辞写强。若原稿发现有价值但对领域意义阐释不足，指出需要连接的具体决策或认识，而不是要求添加宏大背景。

## 跨章节回查

审查同一主张在标题、摘要、引言贡献、方法、实验和结论中的强度是否一致。正文可压缩，但不能省略会改变定理、比较或适用范围的关键条件。附录已有决定性说明时引用其实际位置，再判断正文是否需要简要提示，不能把它当作未提供。
