# 修改后核验

固定原版本、修改版本和本轮材料。沿用 issue_id，逐条阅读原问题、作者所述动作和实际改动。先核验最关键的证据及影响范围，再处理局部修改。

| 状态 | 使用条件 |
| --- | --- |
| `open` | 问题仍在，或当前修改尚未提供关闭依据 |
| `partially_resolved` | 一部分已解决，必须明确剩余条件 |
| `resolved` | 原问题的关闭标准已由可核实材料满足 |
| `resolved_by_narrowing` | 主张已收缩或删除，相关全文同步修改；原强主张仍未获验证 |
| `withdrawn` | 原审稿意见因核对原稿、规则或计算后确认不成立，应撤回并说明原因 |
| `not_assessable` | 缺少本次核验需要的材料，不能判断是否解决 |

对 `resolved`、`resolved_by_narrowing` 记录核验版本、具体材料位置、实际检查和剩余边界。作者说“已修复”、新增仓库链接、增加图表数量或调低语气，不独立构成关闭。

关闭状态绑定原问题的范围。只核验 Methods 与一个摘要句时，可以说明“在这些已提供片段内关闭”，并记录 `verified_scope`；未见全文的同步情况仍为 `not_assessable`。若原问题本来要求全文同步，则整体问题只能记为 `partially_resolved` 或保持待核验，不能用局部修复认证全文。

若原报告误读已有附录，应标记 `withdrawn`，不要要求作者为审稿者误读新增实验。若作者修改了算法、数据划分或实验协议，检查受影响结论是否仍使用旧结果。对未受影响的部分不重复启动完整审查。

关闭技术问题后重新评估贡献：删除关键理论保证可能使经验结果仍成立，但改变论文的新颖性或目标适配度。分别说明“证据问题已解决”和“剩余贡献是否充分”。

复审报告按 [模板](../../assets/templates/recheck-report.md) 直接填写。新的问题使用新编号，说明由何项新证据触发；旧问题即使措辞变化仍保持原编号。
