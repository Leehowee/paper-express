# 路线对比与方法主流程

图中每条箭头应表示明确关系：数据变换、条件输入、损失依赖或参数更新。用形状、线型和标签区分这些关系，并与正文变量一致。

## 套路 A：同输入、同终点、不同处理

使用 D01 / PPTX 第 1 页。行表示路线，列表示共享阶段。对齐输入、处理、表示和输出；在确实不同的位置增加标注。共同模块使用相同名称、大小和颜色。各路线所需标签、预训练、先验和测试时信息写在对应行下方。

直接填充：

```text
{{已有路线}}  {{相同输入}} → {{已有关系/操作}} → {{共同任务模块}} → {{共同输出}}
             前提：{{该路线实际依赖的信息或假设}}
{{本文路线}}  {{相同输入}} → {{改变的关系/操作}} → {{共同任务模块}} → {{共同输出}}
             改变：{{实际新增能力或被放宽的假设}}
```

比较的对象应是有来源的代表路线，不将所有前人工作画成一个虚弱的概括。图中标明的能力是定义或可验证结论；“更准”“更稳健”需要结果证据。

## 套路 B：总览—关键模块展开—训练与推理

使用 D02 / PPTX 第 2 页。按输入到输出排列总览；仅展开承担贡献的模块，普通编码器保留紧凑表示。模块内部可用矩阵、概率、筛选或匹配对象表达操作，比无意义的多层矩形更清楚。

填入 `{{输入及维度}}、{{表示}}、{{模块操作}}、{{条件输入}}、{{输出}}、{{损失/更新目标}}`。给焦点模块标注公式号或伪代码行。虚线只使用一种明确含义；如果既需要训练更新又需要可选路径，使用不同线型并给图例。真实方法没有某个回路时删除该回路。

先制作原生对象，再输出 SVG/PPTX。D 类模板由同一场景 JSON 生成；改变节点位置、标签和连线后重跑。保存后重开检查箭头及对象独立性。

Solid arrows denote {{MEANING}}; dashed arrows denote {{MEANING}}. {{FROZEN/TRAINABLE_SCOPE}}. The expanded component corresponds to {{EQUATION/SECTION}}.

稿件较短时保留读者复原方法所需的完整路径，把细粒度模块展开移至附录；不能删去决定方法含义的监督和推理步骤。
