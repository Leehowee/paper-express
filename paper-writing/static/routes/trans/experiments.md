# Trans：Experiments

直接起草或润色时，使用 [成段模板与改写示例](../../../assets/templates/trans/experiments.md)。下文用于判断章节内容、证据与完成要求。

## 章节任务

系统回答方法是否有效、关键设计是否必要、收益来自何处，以及在什么条件下有效。实验章节围绕主张推进，研究规模和表格数量本身不构成充分证据。

## 必要输入

原始或可核查的结果、数据划分、基线实现、指标、选择协议、随机性来源、硬件与成本、设计对照和失败情况。结果尚未完成时，交付实验计划或带明确待补标记的章节，不生成虚构结果。

## 证据安排

| 要回答的问题 | 适合的证据 |
| --- | --- |
| 是否改善目标任务 | 同一协议下的主结果与强基线 |
| 哪个设计带来收益 | 删除、替换、匹配资源或交叉控制 |
| 机制解释是否可信 | 直接机制指标与区分竞争解释的干预 |
| 理论与实现是否一致 | 条件核对、数值误差、目标轨迹或反例测试 |
| 何时适用、何时失效 | 难度、噪声、缺失、分布变化与失败分析 |
| 代价是否可接受 | 训练、推理、存储、通信或调参成本 |

选择与论文主张相关的证据，不机械执行全部实验类型。默认在正文展开关键分析及其解释；补充材料仅按条件入口启用。

## 章节推进

### 1. 研究问题与实验设置

用少量可判断的问题串起后续小节。说明数据覆盖什么条件、比较为什么公平、主要指标衡量什么。披露训练/验证/测试划分、信息可见性、预训练与外部数据、标签或真实簇数先验、参数选择依据、重复次数和误差含义。

测试集不得承担未披露的模型选择职责。若已有材料采用了真值挑选最好参数或最佳重复，准确记录其性质和局限，不润色成无监督选择或一般部署表现。

### 2. 主结果

先给总体比较，再选最有解释力的差异。区分协议一致的直接比较、不同资源的参考比较和理想上界。读者应知道数值来自复现、原文还是新实验。

解释主要趋势、例外和实用含义，不逐行朗读表格。缺失数值分别标明未运行、超时、内存不足或无公开实现；不可作为零值。排除基线要说明真实理由，复杂度较高本身不意味着比较不公平。

### 3. 关键设计与机制

消融应针对贡献中的具体解释。目标与求解器同时改变时，考虑交叉组合；多个模块存在依赖时，说明被删模块的功能如何替代，避免无效变体造成虚假优势。匹配训练预算、模型容量和可用信息。

中间表示、权重或可视化只能提供相应层次的证据。机制主张需要直接指标或有效对照，不能仅凭最终精度更高作因果归因。

### 4. 稳健性、代价与边界

参数分析说明取值范围、默认值及确定方式；展示敏感区域及其代价，不以单个最优点宣称稳定。噪声与缺失分析区分合成过程和真实数据，注明生成机制及重复单位。

运行时间说明硬件、实现、数据规模、计时范围与是否包含预处理、搜索和外部模型调用。理论复杂度和实测速度互相解释，但不能互相替代。训练曲线说明经验行为，理论性质按命题条件另行表述。

代表性案例补充定量结果，失败案例帮助限定结论。说明选择方式和总体覆盖，避免用少量有利图像推断普遍性能。

## 可改写的结果段

> To test whether [主张], we compare [变体] under [控制条件]. [图/表] shows [关键结果及不确定性], with [重要例外]. This supports [局部结论] within [范围]; [尚未排除因素] requires separate evaluation.

## 接口与完成检查

主结果表、消融表、参数图、效率图和案例通过 [图表接口](../../../interfaces/figures-tables.md) 共享数据口径与编号。理论相关实验与 [理论接口](../../../interfaces/theory.md) 对齐条件，不把验证曲线写成形式化证明。

核对摘要与引言中的每个经验主张；检查统计单位、误差条、提升口径、缺失值和比较资源；确保负面结果和主要代价可见。最终章节应说明“证据支持什么及为什么”，而不只是“做了哪些实验”。
