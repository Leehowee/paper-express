# Trans 期刊路线

将正文组织成完整的研究论证：读者应能理解问题的来源、方法的推导、理论的条件，以及实验如何支持结论。篇幅增加应带来解释与证据的深化，避免扩大背景铺陈或重复强调优越性。

## 结构选择

常见顺序是 Abstract → Introduction → Related Work → Methods → Experiments → Conclusion。根据内容，可以将 Preliminaries、Theoretical Analysis 或 Discussion 独立成节，也可以纳入 Methods 或 Experiments。章节拆分以读者理解为依据。

方法与优化贡献较强时，按“问题定义—目标构造—求解—理论性质—复杂度—关系讨论”展开。统一框架论文先讲一般形式，再讲实例及其选择条件。系统或实证论文可以减少不必要的定理形式，增加协议、对照、误差与代价分析。

## 正文的充分性

- 说明主要假设与变量，并解释目标函数和约束为什么对应研究问题。
- 交代从数学形式到实际算法的过程，包括近似、初始化、停止条件和推理阶段。
- 为主要理论结论提供适用条件、必要证明和解释；证明长时可单列理论章节。
- 系统呈现主比较、设计检验与适用边界，避免用大量相似结果代替关键对照。
- 将局限和实际代价写入相应论证，而非只留在最后一句展望。

## 由会议稿扩展时

仅在存在前作时启用这一要求。清楚引用前作，解释新增问题、理论、算法或证据如何改变原有结论。新增数据集、更多文字或重新排版不自动构成实质扩展。具体披露和重复使用规则按目标期刊核实。

## 使用方式

按当前章节加载 [摘要](abstract.md)、[引言](introduction.md)、[相关工作](related-work.md)、[方法](methods.md)、[实验](experiments.md)、[结论](conclusion.md)。只有补充材料确有需要且允许时加载 [附录](appendix.md)。

实际写作同时加载该节链接的成段模板。引言可选问题驱动、理论驱动或统一框架套路；方法可选目标—求解或框架—组件套路；实验按效果、权衡或条件依赖选择结果段。将材料写成连续初稿；润色时沿用相应改写模式，保留已知事实。

理论请求优先嵌入方法或理论章节，图表请求依据引言、方法与实验的主张发起。对尚未完成的证明和数据保留状态，不为了写成期刊风格而补造内容。
