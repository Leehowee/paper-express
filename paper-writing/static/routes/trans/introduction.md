# Trans：Introduction

直接起草或润色时，使用 [成段模板与改写示例](../../../assets/templates/trans/introduction.md)。下文用于判断章节内容、证据与完成要求。

## 章节任务

建立研究问题的必要性，解释已有进展为何仍留下具体障碍，并让读者理解本文设计与贡献的来源。引言应给出足够的问题深度，同时把详细求解与完整实验留给后文。

## 必要输入

问题背景、最接近的研究路线、目标场景中的限制证据、核心方法思路和已有贡献。若有会议前作，提供前作与新增内容的准确关系。

## 段落推进

1. **任务与价值**：指出研究对象和需要解决的能力或认识问题，避免从过宽的领域历史开始。
2. **已有进展**：按关键路线说明已有方法解决了什么，并承认其有效条件。
3. **具体不足**：给出被忽略的条件、未解决的技术障碍或尚不能解释的现象，说明直接造成什么后果。
4. **问题与挑战**：将缺口表述成可回答的问题。多个挑战应是同一问题的不同方面，且后文分别回应。
5. **核心洞见与方法**：先解释设计原则，再说明关键组件、目标变换或推断过程，交代为何能处理上述挑战。
6. **贡献与范围**：归纳问题、技术、理论或证据中的实质新增内容，指出验证范围。需要时用一小段交代前作扩展。

每个任务可占一段或数段，不固定段落数量。理论驱动研究可从已知结论及条件不足进入；现象驱动研究可用动机实验引出假说；框架研究可从多条路线的共同结构进入。

## 可改写骨架

> Existing approaches achieve [能力] under [条件]. In [目标场景], however, [具体事实] limits [能力或认识]. This raises the question of whether [研究问题]. Our central idea is to [设计原则], so that [预期机制]. We implement this idea through [关键技术] and evaluate it using [决定性证据].

“预期机制”与“已证明机制”按实际证据区分。贡献条目写出新增关系或能力，避免把背景、算法名称和实验规模分别包装成贡献。

## 图表与理论衔接

有实测诊断时，可请求一幅引言实验图展示限制及比较条件；需要澄清不同范式时，可请求路线对比图。按 [图表接口](../../../interfaces/figures-tables.md) 指明图的论证作用，概念示意不可冒充真实实验。引言可以概括理论贡献，完整条件与命题在 Methods 中展开。

## 完成检查

读者能回答“为何研究、已有工作差在哪里、关键想法是什么、证据支持到哪里”。每个挑战对应后文设计或分析；贡献能被证据检查；动机中的现实约束与实验协议一致。不要用“首个”“彻底解决”等未经核实的措辞支撑问题价值。
