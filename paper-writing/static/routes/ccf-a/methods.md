# CCF-A：Methods

直接起草或润色时，使用 [成段模板与改写示例](../../../assets/templates/ccf-a/methods.md)。下文用于判断章节内容、证据与完成要求。

## 章节任务

在有限篇幅内讲清核心变化、完整的信息流和成立条件，使正文足以理解方法并判断其贡献。附录负责细化已经在正文定义的内容。

## 必要输入

任务、输入输出、可见信息、关键目标与组件、实际训练和推理过程、理论状态，以及拟放入附录的细节。优先识别真正需要读者理解的新步骤。

## 正文结构

### 1. 最小充分的问题定义

给出研究对象、必要符号和任务约束。将目标场景中的噪声、缺失、监督或开放条件定义清楚。评价用真值与训练可用信息分开。相关背景只保留后文需要的概念。

### 2. 核心想法与总体关系

先用一段说明解决原则，再给总体目标、关键关系或流程图。对多个模块说明依赖次序，避免从细枝末节开始。图中的模块与后续小节保持一致。

### 3. 关键设计

每个新设计说明解决哪一障碍、采取什么操作、如何进入整体目标或推理过程。保留使设计差异可判断的公式和解释，标准操作可引用可靠来源并将展开过程移入附录。

写清非标准选择，包括归一化、梯度截断、近似求解、候选集、伪标签、阈值与外部模型调用。这些选择若决定算法含义或公平性，需要在正文出现；完整参数表可以后移。

### 4. 理论与算法的必要说明

通过 [理论接口](../../../interfaces/theory.md) 确定可写命题。正文保留命题、关键假设、结论含义与证明思路，长证明放入准确指向的附录。理论本身构成主要贡献时，保留新证明的关键步骤，不能只报定理名称。

若无必要数学主张，不强行补一条定理。经验启发与数学保证分别表达；已有优化算法的性质只有在适用条件满足时才能迁移。近似 E 步、有限迭代或随机更新对保证的影响应明确。

### 5. 训练、推理与成本

交代端到端执行次序、优化目标、输出形成方式及训练/推理信息差异。紧凑伪代码可总结循环和依赖，完整实现放入附录。成本构成贡献时，正文给出主要复杂度与实际成本摘要，包括额外模型或测试时优化的开销。

## 正文与附录配对

| 正文内容 | 对应附录内容 |
| --- | --- |
| 定义、关键假设与命题 | 同一命题的完整证明及依赖 |
| 核心目标与新更新 | 标准变换、全部求解细节、数值处理 |
| 必要训练/推理流程 | 完整网络、参数、提示词和版本 |
| 复杂度或效率结论 | 完整推导、测量设置及扩展结果 |

## 可改写的设计段

> [障碍] prevents [直接方案] from [目标]. We therefore [关键操作], defined by [公式]. Here, [必要符号与条件]. This changes [信息流或优化行为]. [命题/对照] examines [对应主张]; full [证明/配置] is provided in [准确位置].

## 完成检查

按 [图表接口](../../../interfaces/figures-tables.md) 核对流程、变量和公式。去掉附录后，正文仍能说明方法如何工作、区别在哪里及需要什么条件。附录补细节，不首次引入核心组件；尚未完成的理论不写成已证明结论。
