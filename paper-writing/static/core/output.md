# 交付方式

## 先给用户需要的文字

默认先交付可直接使用的章节或修改稿，随后简要说明关键结构调整、证据限制和需要补充的内容。用户只要求局部润色时，返回修改后的文字及必要说明。用户要求大纲时，返回各节职责、证据安排和依赖，不假装已有完整结果。

用户要求初稿时，将所选成段模板转写为连贯正文，消化已有材料并完成句间连接；不要只返回槽位、句型清单或“应该怎么写”。用户要求润色时，返回实际改写后的段落，保留已有事实与引用。用户明确要求空白模板或逐句对照时，再采用相应格式。

整篇写作或大幅重构可附一张紧凑的主张—证据—位置表。涉及正文压缩时，说明哪些内容被合并或转入附录，以及准确去向；不因每次微调生成完整审计报告。

## 区分可用结果与待完成项

- 已有证据支持的句子可以进入正式稿。
- 缺少材料的句子使用 `[待补：具体材料]`，或给出不依赖该事实的可用版本。不得把占位符当成最终投稿稿。
- 需要新增实验、理论核查或图表制作时，另列任务及影响到的主张。
- 新颖性未核实、理论未完成或投稿限制待确认时，说明具体不确定性，不泛化成整篇不可写。

最终检查应说明实际完成的范围。例如“完成章节结构和证据对应检查”与“已编译核对版面”分别报告。接口请求单、普通证明草稿和 Lean 检查通过是不同产物。
