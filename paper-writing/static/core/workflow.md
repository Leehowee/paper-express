# 写作流程

## 1. 确定当前任务

识别用户要求的路线、章节、语言和修改范围。已有稿件、结果表、公式、代码与图表优先复用。写一个段落不要求重新提供整篇论文资料，也不要求先完成 Idea 审查。

最小上下文是研究问题、该段或该节要传达的主张，以及支持它的材料。缺少只影响措辞或局部细节的信息时，说明假设或使用可见待补标记；缺少会改变研究对象、比较含义或结论方向的信息时，提出具体问题，同时推进独立部分。

## 2. 建立主张与证据对应

对整篇写作或明显的结构重组，先用少量条目确定：

| 内容 | 要记录的信息 |
| --- | --- |
| 研究问题 | 对象、条件、尚未解决的关系或能力 |
| 核心主张 | 本文希望读者接受的一个主要结论 |
| 贡献 | 问题、方法、理论、证据各自新增了什么 |
| 证据 | 结果、图表、命题、代码或文献的实际位置及状态 |
| 边界 | 未验证的范围、必要假设、失败与代价 |

为跨模块条目分配稳定编号，例如 `C1`（主张）、`T1`（命题）、`F1`（图）、`TB1`（表）。小任务可直接在上下文中对应，不强制生成额外文件。

整篇或跨模块任务可采用 [共用上下文](../../../shared/research-context.md)，保留假说、成稿结论与不同版本的区别。局部写作不依赖该记录。

## 3. 选择论证路径与章节安排

按研究贡献选择问题驱动、理论驱动、现象与假说驱动或统一框架等路径。路径可以组合，但要解释主要贡献如何由证据建立。为每节先写一句职责说明，删除与其他章节重复且没有新作用的安排。

整篇方法论文通常先整理 Methods 与 Experiments，再完成 Introduction、Related Work、Conclusion 和 Abstract。理论论文可以先稳定定义、命题及证明，再确定验证与应用。写作顺序服务于已有材料，不强制按论文目录起草。

## 4. 分配正文、图注与附录

先确定哪些证据决定中心结论，再决定放置位置。Trans 默认正文完整；会议正文保留判断结论所需的最小充分论证。图注解释展示内容和读图规则，正文解释结果的意义；完整配置和长推导可以按路线安排。

涉及理论时使用 [理论接口](../../interfaces/theory.md)，涉及图表时使用 [图表接口](../../interfaces/figures-tables.md)。接口收到新假设、范围限制或失败后，回改受影响的摘要、引言、方法、实验解释和结论。

## 5. 写成连续论述

起草、润色、压缩、翻译或结构重写时，按 [直接起草与润色](drafting-and-polishing.md) 加载当前章节的成段模板。根据材料选定一套主套路，将字段填成正文，删除不适用的可选段并完成语言衔接。已有稿件结构合理时沿用原结构，以局部改写模式处理。单纯索要写作建议时才以建议为主要输出。

以段落为单位推进：提出本段要点，给出必要定义、依据或比较，说明它如何推动下一步。方法段解释设计的需要、具体操作和作用；实验段说明检验问题、比较条件、关键发现及其含义。不要把材料清单直接拼成正文。

## 6. 检查后交付

检查主张是否超过证据，最近工作是否被准确描述，公式与算法是否一致，关键设置是否可复现，正文引用能否定位到图表、命题与附录。修改一个重要条件时，同步检查其所有引用位置。

有实际稿件与编译环境时，用目标模板编译并检查页数、浮动体、字体与交叉引用。只有文本时，只报告文字与结构检查，不声称版面已合规。完成当前授权任务后交付结果与确实影响使用的待补项。
