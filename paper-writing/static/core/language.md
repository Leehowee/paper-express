# 语言与段落

遵循用户指定的语言。未指定时，沿用现有稿件语言；只有中文研究笔记而需生成英文投稿正文时，先给英文稿，再用简短中文解释必要的结构调整。中文模板中的组织方式同样适用于中文初稿。

## 句子

让主语和谓语尽早出现，一句承载一个主要判断。介绍对象后再解释性质和意义。拆开过长的背景、动机、方案与结果串联，保留明确的因果、比较或条件关系。

使用能够说明动作的动词，例如 define、estimate、optimize、compare、bound、observe。`prove` 对应有明确前提的证明，`show` 对应直接证据，`suggest` 或 `is consistent with` 对应尚未排除替代解释的推断。不要用 `guarantee` 描述有限实验中的平均改善。

## 段落

一段完成一个论证任务。首句给出对象和要点，后续句子补充定义、依据、比较或限制，末句在需要时引出下一步。段落之间使用逻辑关系衔接，少用只有顺序功能的套话。

方法组件第一次出现时交代其职责，缩写第一次出现时展开。减少无助于区分设计的模块名。文献、公式和图表引用靠近它们实际支持的判断。

## 常见改写

| 模糊写法 | 改写方向 |
| --- | --- |
| 该问题十分重要 | 指出受影响的任务、条件或认识 |
| 现有方法存在不足 | 写出具体假设、失败场景及后果 |
| 我们提出三个创新模块 | 解释关键设计改变了哪种关系或计算过程 |
| 实验证明方法显著优越 | 给出比较设置、指标、改善幅度及不确定性；没有统计检验时慎用显著性语言 |
| 理论保证实际性能 | 给出命题对象、条件与保证范围，单列经验效果 |
| 首次、最先进、任意场景 | 核实文献和适用范围，或改为具体差异与已检验范围 |

章节指导中的方括号和成段模板中的 `{{FIELD}}` 表示待填内容；`[待补：具体内容]` 表示仍缺少的材料。按真实研究填充并完成语言衔接，不机械保留整套句型或把英文示例翻译成固定套话。
