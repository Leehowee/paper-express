# 使用示例与路由判断

这些示例用于说明如何选择文件和处理证据，不含虚构的研究发现，也不表示已在真实论文上完成写作、形式化或投稿验证。

## 可以直接复制的请求

下列请求可配合本地 `SKILL.md` 使用；已安装或已加载该技能时也可用 `$paper-writing` 作为名称。把方括号替换成实际材料。

```text
使用 paper-writing，按 Trans Methods 的“目标—求解”套路直接写英文初稿。
材料：[问题定义、符号、目标函数、更新过程、实现和已完成的理论结果]。
先给连续正文，再列必要待补项。
```

```text
使用 paper-writing，按 CCF-A Introduction 的问题驱动套路写四段初稿。
材料：[任务、最接近工作、具体不足、关键想法、实际证据和边界]。
正文篇幅要求：[已核实要求或暂未确定]。沿用已有引用，不补造文献。
```

```text
使用 paper-writing，润色以下 Trans Experiments 段落。
保留全部数值、比较范围和例外，将逐行复述改成“主要差异—条件—解释”。
原文：[段落]。对应表格或数据：[材料]。先给润色稿，简要说明重要修改。
```

```text
使用 paper-writing，将以下 Methods 改成会议正文的紧凑写法。
正文保留定义、核心操作和必要假设；可用附录内容及位置：[实际材料]。
原文：[章节]。目标长度：[要求]。不存在的附录保留待补位置。
```

首次理解模板用法，可读 [完整填充与润色示例](worked-drafting-example.md)。

## 单独撰写 Trans Methods

请求：“按 Trans 写方法，我已有目标和交替更新代码，收敛证明还没完成。”

加载共用核心、Trans overview、methods 章节指导及其成段模板；读取理论接口。按目标—求解套路直接写定义、设计、求解与已知实现，形成明确理论请求。没有证明时，不写“保证全局收敛”；已有曲线只能按经验观察处理。默认规划必要证明的正文位置。

## 为会议压缩实验章节

请求：“正文超页，请把实验部分压缩，保留核心消融。”

加载会议 overview、experiments、appendix 的章节指导和相关成段模板，以及内容分配规则。核对目标约束，保留决定贡献的对照和重要失败，合并重复叙述，把完整扫描与次要结果移至具体附录位置。实际返回压缩后的正文和移出的补充内容。完成文字压缩不等于版面合规，有稿件环境时再编译检查。

## 只有想法时起草摘要

请求：“方法刚设计好，还没做实验，先写摘要。”

加载相应 abstract 成段模板。交付研究问题和方案明确的暂定摘要，结果位置标明待补，或在用户接受时省略结果句，不写“实验表明”“达到 SOTA”或虚构数字。已有设计保持事实语气；用户确实要研究计划时再采用计划语气。未定投稿路线时，先用共用骨架，保留篇幅配置。

## 理论支撑的会议稿

请求：“主要贡献是一条新界，请把长证明放附录。”

加载理论路径、会议 methods、appendix 和理论接口。正文保留命题、必要假设、关键证明思想及其意义，附录提供完整证明。若主要创新就在某一步推导，正文保留该步骤。Lean 未执行时仅记录未运行，不将文稿证明等同于形式化通过。

## 独立图表任务

请求：“我只想做主实验表，已有 CSV 和各模型配置。”

直接按图表接口形成任务，不要求先写完整论文。核对每列指标、独立重复单位和模型信息条件；数据齐全时由可用图表模块制作，模块未实现时交付表格结构与请求说明。没有重复结果时不生成误差条。

## 不采用附录的期刊稿

请求：“这篇期刊论文所有证明和必要分析都放正文。”

加载 Trans 对应章节，appendix 模板仅作完整性检查。通过独立理论章节、紧凑推导和组织化实验安排承载证据。若目标实际篇幅与必要内容冲突，明确列出冲突与可选调整，不擅自生成补充文件。

## 已有形式化文件但包含占位证明

请求：“Lean 工程能编译，请把方法写成已经严格证明。”

依据理论接口核对实际记录、占位符、额外公理和语义映射。编译成功本身不能排除 `sorry` 或新增假设；未完成审查时保持相应状态。完成当前可用文字，同时明确哪一数学主张尚不能采用强保证措辞。
