# 输出约定与研究衔接

先给研究判断，再给依据与下一步。使用用户的语言，依据任务规模组织内容；局部修改仅更新相关部分。

## 审查报告

完整审查应使读者能够理解以下内容，可按论证需要合并：

1. **总体判断**：推荐的推进方式、主要依据及关键不确定性。
2. **问题重构**：研究对象、具体未知、核心假说或命题，以及问题的价值。
3. **研究价值审查**：分别说明创新性、重要性与可行性的依据、限制和改进方向。
4. **路径分析**：围绕任务瓶颈、竞争解释、机制关系、理论命题或共有结构展开必要分析。
5. **优化建议**：给出主要方案；存在实质取舍时补充备选，并说明选择依据。
6. **验证方案**：明确检验对象、比较条件、判断标准、资源需求和结果分支。
7. **研究主线与边界**：说明目前能够支持什么、尚需确认什么，以及下一项具体工作。

未完成文献核查时明确新颖性结论的暂定性质。将已有结果与拟开展工作分开，结论强度与证据状态一致。

需要直接成稿时，用 [五类成段模板](../assets/templates/idea-review.md) 完成当前路径的判断与问题重构。模板服务于现有材料，不用填空形式替代实际分析。

## 路径对应的核心产物

| 路径 | 需要明确的内容 |
| --- | --- |
| 问题驱动 | 任务需求、关键约束、瓶颈依据、成功与失败标准 |
| 假说与反常现象驱动 | 竞争解释、差异预测、判别检验和否定条件 |
| 机制驱动 | 干预、中间过程、结果变量、替代解释和归因条件 |
| 理论驱动 | 对象、量词、假设、命题、已有结果和证明或反例计划 |
| 统一框架驱动 | 共有结构、可变部分、实例化规则和适用范围 |

表格、图示或条目服务于判断。能够用简洁文字说明的内容，无需另建记录表。

## 后续任务的交接

后续写作使用研究问题、核心主张和证据链；理论研究使用准确命题、假设及证明状态；图表设计使用待呈现的关系、比较目的与数据来源。

复杂项目可采用以下结构记录；简单任务保留在报告中即可：

```yaml
research_question: 一句话科学问题
primary_route: 主要研究路径
secondary_routes: 按需采用的辅助路径
core_claim_or_hypothesis: 核心主张或待检验命题
scope_and_assumptions: 研究对象、条件和假设
closest_work_and_delta: 最接近工作及实质差异
novelty_status: 核查程度与检索范围
evidence_available: 已有证据及其来源
decisive_test: 能够改变判断的关键检验
falsifying_outcome: 将推翻或限制主张的结果
resource_constraints: 资源条件与估算依据
unresolved_issues: 关键未知及其影响
decision: 推进建议及理由
```

上述内容是字段说明。实际使用时填写有依据的信息，缺失内容保留为未知；不以示例补充事实。后续任务沿用已确认的问题、术语和结论边界。
