# 统一框架驱动

统一框架研究识别不同问题或方法之间的共有结构，通过一致的建模与求解原则建立联系，并明确哪些差异需要保留。

## 论证逻辑

`共同问题或结构 → 现有方法的联系与差异 → 统一表达 → 可推导原则 → 具体实例 → 适用范围`

框架的价值来自统一后获得的新认识、推导能力或可验证能力。共同命名和形式相似需要进一步转化为实质联系。

## 形成研究问题

1. **确定统一对象。** 说明哪些问题、方法或条件需要共同处理，以及统一的研究价值。
2. **识别共有结构。** 明确共同变量、目标、约束、接口或求解原则，给出它们存在的依据。
3. **保留关键差异。** 区分框架不变的部分与随任务变化的部分，避免通过过度抽象抹去真实限制。
4. **解释已有方法的位置。** 说明其属于特例、对照还是互补方案，并识别无法纳入的情况。
5. **建立可检验承诺。** 明确统一表达应带来哪些关系、原则或能力，以及如何验证。

自然或物理类比可以启发框架设计，但需要说明实际采用的原则及其验证方式。类比本身不承担理论保证。

## 审查重点

- **创新性**：已有框架是否覆盖同样的抽象；当前工作是否新增关系、训练或求解原则、兼容能力或适用条件。
- **重要性**：统一是否澄清共同限制、减少不必要的专用假设，或使原本分离的问题能够相互解释。
- **可行性**：共有结构能否在具体对象中实现，扩展所需修改是否仍符合统一原则，验证范围是否与资源匹配。

多个相似场景中的成功主要支持相应范围的稳定性。广泛适用的主张还需覆盖具有实质差异的条件。

## 验证与优化

先用代表性实例检验框架是否具有明确实现，再选择能够暴露适用限制的实例，检验所声称的迁移与统一能力。

按需建立实例化关系：

`场景 → 共同结构的具体对应 → 必要修改 → 被检验的主张 → 适用条件`

验证维度应由主张决定，可涉及对象结构、任务目标、资源条件、监督信息或方法类别。每项通用性主张都应有相应的实例、分析或证明。

对经验收益，区分框架变化与额外数据、容量或计算的影响。对理论收益，说明统一形式化产生了什么可用结论。

- 证据仅覆盖单一实例时，限定当前贡献，并给出进一步检验框架范围的方向。
- 不同实例需要改变核心原则时，重新审查共有结构是否成立。
- 收益主要来自附加资源时，调整比较或收敛框架自身的贡献。
- 验证资源有限时，优先选择能检验不同承诺的实例，分阶段扩大范围。

## 问题表述

> 〔若干问题或方法〕共享〔结构或限制〕，但其联系与适用条件尚未得到充分说明。拟通过〔统一表达〕建立〔共同原则〕，明确〔不变部分与可变部分〕，并在〔具有判别力的实例或条件〕中检验其价值与边界。

最终形成统一对象、共有结构、实例化规则、验证维度与适用范围。
