# 理论驱动

理论驱动研究以明确的数学未知为中心，通过证明、推导或反例确定性质、条件与界限。正确性、创新性和研究意义需要分别评价。

## 论证逻辑

`数学对象 → 已有结果 → 未决问题 → 精确命题 → 必要假设 → 证明或反例 → 研究含义`

理论可以构成主要贡献，也可以指导设计或解释现象。明确其在研究中的作用，再判断命题是否与核心问题相连。

## 明确理论任务

- **建立理论结果**：研究新的条件、界限、等价关系、反例或不可能性。
- **指导方法设计**：由目标和约束推导结构、学习规则或可计算的选择。
- **解释经验现象**：提出能够说明观察并产生可检验预测的数学关系。

辅助性定理应对研究主线产生实际作用；理论作为主要贡献时，可直接以知识推进说明价值。

## 命题审查

建立 `对象 → 假设 → 命题 → 已有结果 → 证明障碍 → 研究含义` 的对应关系。

1. **对象与量词。** 明确变量、空间、随机性、算法版本及结论覆盖的对象。
2. **假设与适用性。** 区分证明所需条件与实际问题可满足的条件，检查是否存在循环前提。
3. **非平凡性。** 说明命题相对定义、常用恒等式和已有定理增加了什么认识。
4. **结论强度。** 区分充分与必要、局部与全局、期望与高概率、有限与渐近等性质。
5. **信息价值。** 检查界限、常数和尺度依赖是否有意义，是否能够约束认识或指导选择。
6. **实现对应。** 检查近似、离散化、估计误差及训练规则变化是否影响理论适用性。

一个命题成立，不自动证明相关方法收敛、优于其他方法或具有更广泛的能力；每项结论需要对应的前提与论证。

## 审查重点

- **创新性**：比较命题、假设强弱、界限量级及适用范围，判断新增内容是否超出已知结果的直接应用。
- **重要性**：说明结论澄清了什么未知，排除了什么可能，或为哪项设计提供了依据。
- **可行性**：识别关键引理、已有数学工具和真正的证明障碍，先检查可处理的特例与退化情形。

需要作新颖性判断时核查最接近的理论结果。当前材料中尚未解决的问题，应与领域尚未解决的问题区分。

## 验证与优化

优先开展能够暴露命题问题的检查，包括低维特例、极限情形、假设移除、反例构造或关键引理证明。数值结果用于发现规律和检查推导，不能替代证明。

- 合法条件下出现反例时，撤回或修正命题，并重新评价修正后结论的价值。
- 所需假设与实际对象不符时，调整建模、补充误差分析或限定应用范围。
- 结论属于已有结果的直接应用时，明确其作为理论依据的作用，再判断是否存在独立贡献。

需要形式化证明时，交接定义、命题、假设、依赖和当前证明状态。仅在相应代码经过实际检查后报告 Lean 验证完成，并说明验证覆盖的命题。

## 问题表述

> 对〔数学对象〕，已有结果在〔条件〕下给出〔性质〕，仍需明确〔未决关系或边界〕。拟研究〔精确命题〕，通过〔证明路线或反例〕确定其成立条件，并说明其对〔认识或设计〕的意义。

最终形成准确命题、假设分析、已有结果比较、关键证明任务及与研究主线的联系。
