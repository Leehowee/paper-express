# 问题驱动

问题驱动研究从明确的能力限制出发，识别影响目标实现的关键未知，并通过可检验的研究方案回答这一未知。

## 论证逻辑

`任务需求 → 已有能力 → 具体限制 → 关键未知 → 研究方案 → 任务评价 → 适用边界`

先建立任务需求与现有能力之间的差距，再判断该差距是否包含有价值的研究问题。问题的重要性应由其后果说明，方案的必要性应由其作用说明。

## 形成研究问题

1. **限定任务与条件。** 明确研究对象、使用环境、必要约束和最终目标，确定评价的基本单位。
2. **定位具体限制。** 说明现有方法在哪些条件下不能满足需求，并区分已观察到的瓶颈与尚待验证的诊断。
3. **提炼关键未知。** 将宽泛的性能诉求转为有关信息、条件、结构或能力边界的问题。
4. **建立设计依据。** 说明候选方案改变了哪个限制，以及预期如何影响目标结果。
5. **确定成功判据。** 让评价直接对应研究问题，同时识别失败条件与可能的代价。

已有方法的有效部分应保留在问题分析中。新方案可以补充现有能力、扩展适用条件或改变关键约束，无需将此前路线概括为全面失效。

## 审查重点

- **创新性**：相同条件下的问题是否已被解决；当前变化是否产生新的能力、适用范围或研究认识。
- **重要性**：瓶颈是否实质影响任务目标；预期收益是否能够传递到最终结果。
- **可行性**：所需数据、反馈、基线与评价条件是否具备；候选方案是否能够在实际约束内实施。

多阶段任务需要检查环节依赖、失败传播和额外开销。整体能力应按整体任务评价，局部收益应明确其贡献范围。

## 验证与优化

优先选择能够暴露关键瓶颈的代表性场景，将现有方法、合理的简单改进与候选方案放在可解释的条件下比较。比较范围由研究主张决定。

涉及资源取舍时，同时评价目标质量与完整成本。归因分析应控制主要影响因素；实际系统比较应说明各方案达到相应表现所需的条件。

根据证据调整研究方向：

- 瓶颈依据不足时，先开展诊断，确定真正限制目标的因素。
- 简单改进已满足需求时，重新判断是否仍存在独立的科学问题。
- 证据仅覆盖部分环节时，将问题收敛到能够可靠验证的范围。
- 效果明确而解释尚不充分时，保留已支持的能力结论，并安排机制分析。

## 问题表述

> 在〔对象与条件〕下，现有方法能够〔已有能力〕，但在〔具体情形〕中仍受〔限制〕影响。尚不清楚〔关键关系或条件〕。拟通过〔研究方案〕，在〔比较与约束〕下检验〔目标结果〕，并确定其适用范围。

表述应使任务需求、科学未知、设计依据与评价标准相互对应。最终形成明确的问题、瓶颈依据、成功判据和优先验证方案。
