# GH-J：JustGRPO 如何从质疑默认优势走向简化方案

本地文件名为 `JustGRPO.pdf`，实际题名为 *The Flexibility Trap: Rethinking the Value of Arbitrary Order in Diffusion Language Models*，首页日期 2026-06-09。本文按所提供版本分析，不声称已核实其最终出版或获奖状态。见 [来源索引](../source-index.md)。

## 核心问题的形成

引言把 diffusion LLM 的两个特点拆开：并行解码与任意顺序生成。随后检验后一特点在数学和编码推理任务中的价值，而不否认前者的用途。[PDF pp.1–3]

**本技能重构的问题**：在实际有限预算的解码与 RL 训练设置中，任意顺序提供的形式自由度是否增加可探索的正确解，还是因置信度驱动的顺序选择而提前限制分支？若后者成立，训练是否可以简化，同时保留并行推理？

## 从观察到方案的论证链

| 环节 | 论文证据 | 对 idea 审查的启发 |
| --- | --- | --- |
| 发现两个目标不同 | 小 k 的表现与大 k 的覆盖不一致 | 先判断自己要优化的是哪种能力；pp.2、4–5 |
| 检验自由度 | AR 与任意顺序比较；改变块大小 | 自由度更多并不自动意味有效搜索更强；pp.4–5 |
| 提出机制解释 | 逻辑分叉 token 被延后，其条件熵变化 | 将“更灵活”具体化为可观察的决策过程；p.6 |
| 质疑保留复杂性的必要性 | 对任意排列处理的 RL 近似与开销提出问题 | 方案优化可以来自删除未经证实的要求；p.7 |
| 建立简化方案 | 将训练中的生成分解为 AR policy，使用 GRPO | 简化需保持任务可定义、似然可计算；pp.7–8 |
| 检查代价是否被转移 | 统一设置比较、并行解码和 wall-clock 分析 | 训练简化、训练便宜、推理并行是不同主张；pp.8–10 |

## 哪些对照使论证更扎实

Table 1 明确说明部分对比引用不同论文、采用的配置并不完全一致；Table 2 进一步给出匹配配置的复现实验。这种区分应进入审查模板：系统级展示不能代替机制或算法归因。[pp.8–9]

Appendix D 检查随机顺序是否是替代方案：随机推理顺序的覆盖与单次正确率，以及固定随机排列的 RL 变体分别评估。它说明“限制自由度是否足够”还需要比较具体采用的限制。[pp.17–19]

## 需要保留的边界

- 大 k 的 pass@k 仍是有限采样代理，不提供 RL 可达能力的严格普遍上界。[p.4]
- 机制分析主要针对置信度引导、半自回归等所测设置；不能外推到所有可能的 diffusion sampler。[pp.4、17]
- 特定 token 的熵与探索解释之间仍有推断环节；更多可区分干预会加强因果判断。词语列表和注意力式可视化本身不等于证明。[p.6；pp.17–18]
- 保留 bidirectional architecture 和并行解码，不等于所有形式的双向修正能力都已验证；原文将后者列为后续方向。[p.19]
- 形式简洁不等于计算便宜：精确概率比有逐位置计算开销，文中 wall-clock 比较在 16×H100 上进行；资源可行性需按用户条件另算。[p.10]

采用 [假说路径](../routes/hypothesis-driven.md)，机制分析充分时辅以 [机制路径](../routes/mechanism-driven.md)。最有价值的迁移是先验证某种“优势”是否真的服务目标，再决定需要保留多少复杂性。
