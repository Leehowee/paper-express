# Idea 与科学问题审查

将研究构想收敛为明确的科学问题，判断其知识增量、研究价值与验证条件，并提出有依据的优化建议。以问题能否得到可靠回答作为审查的中心。

## 1. 识别研究任务

从已有材料中识别研究对象、当前认识、关键未知、候选方案、已有证据和资源约束。区分用户希望解决的实际困难与希望回答的科学问题。

对初步构想，优先明确问题与验证路径；对已有结果，检查结果实际回答了什么，以及解释是否超出证据。后续修改复用已确定的问题、术语和条件，只更新受影响的判断。

只有缺失信息会实质改变核心判断且无法从上下文确定时才提问。其余缺口明确标注，并继续完成可独立进行的分析。

## 2. 选择审查路径

读取 [共同审查标准](references/common-review.md)，再根据主要未知选择相应路径。混合研究确定一个主路径，按需结合辅助路径；无需依次执行全部模板。

| 路径 | 适用情形 | 核心审查对象 |
| --- | --- | --- |
| [问题驱动](references/routes/problem-driven.md) | 现有能力在特定条件下受到明确限制 | 任务需求、关键瓶颈与成功判据 |
| [假说与反常现象驱动](references/routes/hypothesis-driven.md) | 既有解释存在疑点，或观察与预期不一致 | 竞争解释、差异预测与判别证据 |
| [机制驱动](references/routes/mechanism-driven.md) | 希望解释现象的产生过程，并通过干预改变结果 | 机制关系、中间过程与因果归因 |
| [理论驱动](references/routes/theory-driven.md) | 希望确定成立条件、性质、界限、等价关系或不可能性 | 数学命题、假设、证明与反例 |
| [统一框架驱动](references/routes/framework-driven.md) | 多个问题具有共同结构，需要一致的建模或求解原则 | 共有结构、实例化规则与适用范围 |

按研究要回答的问题选择路径。方法名称、技术类别和表达形式仅提供线索，不决定研究类型。

## 3. 明确问题与研究主线

先区分已有认识与尚未解决的部分，再说明拟回答的具体问题。知识缺口应指向未知、争议、未检验条件或能力边界，并具有可说明的研究价值。

形成彼此一致的三项表述：

- **研究问题**：在什么对象与条件下，尚不清楚什么。
- **核心假说或命题**：拟检验的关系、解释或性质是什么。
- **研究路线**：通过什么比较、干预、推导或反例回答问题，结论适用于哪些条件。

研究问题应能独立于候选方案的名称成立。某种方法尚未用于特定任务，不足以独自确立知识缺口；还需说明未被回答的问题及其价值。

## 4. 评估研究价值并优化方案

分别评价创新性、重要性与可行性，为每项判断给出依据、关键未知和改进方向。

- **创新性**：相对于最接近的工作，新增了什么认识、条件、解释、理论结果或可验证能力。
- **重要性**：问题的答案将如何改变学术认识、研究选择或实际能力。
- **可行性**：现有数据、方法、数学基础和资源能否支持有判别力的验证。

需要判断现实文献中的新颖性时，检索并读取相关原始来源；核查不完整时，将结论限定为暂定判断。综合决策依据各项论证，不用加权总分掩盖关键缺口。

优先完善问题定义、核心假设、比较条件和证据安排。每项方法调整都应对应明确的研究需要，并说明为何值得增加、修改或移除该设计。

## 5. 提出验证与推进建议

设计能够改变研究判断的最小验证方案，说明检验对象、比较条件、评价标准、资源需求及可能结果的含义。

分别考虑支持核心假说、削弱或推翻假说、尚不足以判断的结果。根据先导结果决定是否扩大验证范围；出现反例或条件差异时，调整命题、解释或适用范围。

按 [输出约定](references/output-contract.md) 交付判断、问题重构、审查依据、优化方案和下一步。使用 [可直接填写的审查与重构模板](assets/templates/idea-review.md)，选当前路径写成实际结论，不仅列写作建议。模板包括五种问题主线、共用判断段、最小验证和交接段；按 [manifest.yaml](manifest.yaml) 选择所需内容。

## 6. 校准结论强度

- 将已观察事实、文献主张、分析推断与待检验假设分开表述。
- 使结论层次与证据层次一致，分别审查效果、机制、理论保证与外推范围。
- 将未发现证据与不存在该现象区分；将符合某种解释与能够区分竞争解释区分。
- 理论结论应明确前提与对象；证明草稿、数值验证和形式化验证分别报告状态。
- 研究意义由问题和证据支持，发表层次与奖项仅用于识别文献背景。
