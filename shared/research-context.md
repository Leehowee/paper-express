# 跨模块上下文与状态

仅在任务跨越多个模块、版本变化或判断出现冲突时读取。局部写作、单个证明或单张图表可以直接传递必要信息，不要求建立项目台账。可复制 [上下文模板](../assets/templates/research-context.yaml)。

## 保留同一个研究对象

| 信息 | 交接时保留什么 |
| --- | --- |
| 问题与范围 | 研究对象、条件、所问关系、目标终点 |
| 主张 | 稳定 `claim_id`、准确表述、是假说还是成稿结论、成立条件 |
| 证据 | 实际文件、版本和位置；是观察、文献、证明、反例还是示意 |
| 目标 | venue、年份、稿件类型及已核实规则；未知不填猜测 |
| 任务 | 当前要完成什么、调用模块、所需产物与影响位置 |
| 未决事项 | 具体缺口、对哪条主张有影响、什么材料可以解决 |

沿用已有编号，`C1` 与 `C01` 都可以，不为排版方便重编号或误判为两条主张。发生实质变化时保留原主张与修订版本，说明哪些条件、结论或比较改变了。章节、公式、图表编号沿用稿件，不凭空新建已经存在的对象。

证据材料的可信范围不能因跨模块传递而扩大。Idea 中的候选解释进入写作时仍是候选解释；理论中条件命题的通过不等于实际算法的保证；图表生成成功不等于数据正确或机制成立；审稿问题被收缩主张解决不等于原主张得到证明。

## 分开报告四类状态

| 对象 | 状态来源 | 使用含义 |
| --- | --- | --- |
| 主张的证据支持 | 审查模块的 `supported / partial / unsupported / refuted / not_assessable` | 只针对指定主张、版本和检查范围；未审假说可以暂记 `not_assessable` 并注明其假说身份 |
| 数学命题 | 理论模块的 `candidate / proof_draft / proved / gap / refuted` | 区分未证、已证和有反例；不同命题各有结果 |
| Lean 工程与语义 | `not_formalized / source_unrun / check_failed / checked`，并列证明完整性、语义映射与应用义务 | 状态绑定具体工程和命题；成功编译不能代替映射检查 |
| 图表产物 | `layout_only / generated / checked_with_limits / checked`，并列数值、语义、视觉、编辑回存检查 | 状态绑定具体文件及本次约定的检查，不能代替研究验证 |

审稿问题关闭状态另外使用 `open / partially_resolved / resolved / resolved_by_narrowing / withdrawn / not_assessable`。不要用一个全局 `verified: true` 覆盖以上差别。写作通常没有独立科学“验证通过”状态，应说明完成了文字、结构、引用、编译或版面中的哪些检查。

对代码或源码已有但未执行的情况保留未运行；已执行且失败时记录失败阶段。环境失败与命题被反驳是两回事。多个 Lean 片段的状态不同，应逐个记录，不能由一个通用引理的日志覆盖整个论文。

## 处理变更与冲突

以实际材料及其版本为依据核对冲突，不按模块名或最近一条摘要决定谁正确。发现矛盾时，保留双方位置，定位是版本差异、定义变化、统计口径变化还是推理错误；不能核实时，只暂缓依赖该事实的结论。

按依赖修订：先确定研究事实或数学结论，再更新图表与表注，随后同步摘要、引言贡献、Methods、实验解释和结论。未受影响的文字和产物不必重做。审查发现需要新数据或实验时，返回明确研究任务；写作与图表模块不能生成缺失的实证证据。

## 模块缺失与独立使用

五个模块都可独立处理其核心任务。单独复制模块后，相邻模块和原始 PDF 的链接可能不可用；已有定义、材料与模板仍可使用。仅在确实需要缺失模块时，输出包含主张、材料、条件和返回要求的任务说明，继续完成不依赖它的工作。

本文件统一交接语义，不建立自动调度器，不改变用户已经授权的范围。
